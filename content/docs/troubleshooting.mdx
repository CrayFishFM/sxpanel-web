Most sxPanel problems come down to the `monitor/` folder swap, the FXServer
launch command, a permission the admin does not have, or the Discord bot
configuration. This page covers the most common ones and points you to the
**Problems** section of the page that owns each feature, where every error
message is listed exactly as shown.

## The panel URL does not open

<Callout>
  sxPanel prints a setup URL to the console on first boot. If you started
  FXServer **with** `+exec server.cfg`, the panel may not have started. Launch
  without it — sxPanel manages the server lifecycle for you.
</Callout>

- Confirm the `monitor/` folder contains the sxPanel build and that FXServer
  loaded a resource literally named `monitor` (`txadmin` on FiveM Enhanced
  gen9 servers; this is required — see the
  [Events API](/docs/events-api) note on the resource name).
- Check the console for the printed URL; it usually runs on
  `http://localhost:40120`.
- If the port is in use, set the `TXHOST_TXA_PORT` environment variable to an
  alternate port (see [Configuration](/docs/configuration)).
- A `FATAL ERROR: E<code>` line means a requirement failed. The code table is
  in [Installation problems](/docs/quick-start#problems).

## Migration from txAdmin appears broken

Existing `txData` directories work without modification. If something looks off:

1. Verify you replaced the entire `monitor/` folder, not just part of it.
2. Confirm `txData` is in its original location and is readable by FXServer.
3. Restart FXServer so sxPanel re-scans the data directory.

See [Migrating from txAdmin](/docs/migrating-from-txadmin) for what is migrated, the backups and the error messages.

## You cannot sign in

- `Wrong username or password!`, `Wrong PIN.` and two-factor errors are
  explained in [Admins and permissions](/docs/permissions#problems).
- `Too many attempts. Blocked for 15 minutes.` is the sign-in limiter. Wait, or
  restart FXServer. Behind a reverse proxy, turn on **Trust Reverse Proxy** so
  one user's attempts do not block everyone; see
  [Configuration](/docs/configuration#problems).

## An action says you do not have permission

Almost every "permission" message means the admin account lacks one specific
permission. The message or the page's **Who can use it** section names it.
Add it in the Admin Manager; see [Admins and permissions](/docs/permissions).
Some actions need **All Permissions** (addon and update management) or the
master account (the [Danger Zone](/docs/settings)).

## The Discord bot is offline

- Double-check the bot token and "Bot Enabled" toggle in the panel's Discord
  settings.
- Make sure the **Server Members Intent** and **Message Content Intent** are
  enabled for your bot application in the Discord Developer Portal — the bot
  needs both to resolve roles and read command interactions.
- Re-invite the bot with the correct scopes if it was removed. Slash commands
  need the `applications.commands` scope.
- Open **System → Diagnostics → Discord Bot** to see the last bot error and
  restart the runtime; see [System pages](/docs/system#discord-bot).

More in [Discord bot problems](/docs/discord#problems).

## Players can't connect after enabling whitelist

- Confirm the active whitelist workflow matches what you intend (Admin Only,
  Discord Member, Discord Role, or Manual Review).
- For Discord Role workflows, verify the role IDs configured in Discord settings.
- Remember only one workflow is active at a time — check the
  [Whitelist](/docs/whitelist) guide if you expected multiple checks to combine.
- If the [connection queue](/docs/settings/queue) is on, players also pass the
  queue after the whitelist check.

See [Whitelist problems](/docs/whitelist#problems).

## Charts or console look empty

Insights and the live console depend on the server running through sxPanel. If
you bypass the panel and start FXServer directly, telemetry won't be captured.
Always start via sxPanel so it can instrument the server. Individual Insights
cards also stay empty until enough data exists; each message is explained in
[Insights problems](/docs/insights#problems).

## A page is missing from the sidebar

The admin either lacks the permission for the page or the page was switched
off in **Settings → Panel Features**. See [Settings](/docs/settings) and
[Admins and permissions](/docs/permissions).

## Still stuck

If none of the above helps, join the [Discord community](/docs/discord) or open
an issue on [GitHub](https://github.com/Snipzil/sxpanel). Include the relevant
JSONL log lines from the system logger — they make diagnosing much faster. You
can also send a support report from
[System → Diagnostics](/docs/system).
